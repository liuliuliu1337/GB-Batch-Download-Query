# GB 标准批量下载查询器

批量查询中国国家标准（GB / GB/T）信息并下载全文 PDF 的命令行工具。

数据来源为**国家标准全文公开系统**（`openstd.samr.gov.cn` / `c.gb688.cn`），通过模拟浏览器访问、OCR 识别验证码完成下载，不涉及任何破解或绕过授权的手段——能下载的都是该系统本身就公开提供全文的标准。

> 本项目基于 [suwadaimyojin/gb-downloader](https://github.com/suwadaimyojin/gb-downloader) 二次开发，针对 2026 年 11 月站点改版做了完整适配。

---

## 功能特性

- **批量查询**：从 txt 清单批量检索标准号，导出 Excel（标准名称、类别、状态、发布日期、实施日期等）
- **批量下载**：自动获取会话 → OCR 过验证码 → 下载 PDF，逐个标准独立会话，互不干扰
- **验证码自动重试**：识别失败自动换图重来，默认最多 10 次
- **自动跳过无效标准**：已废止 / 未收录的标准页面没有"下载标准"按钮，程序会直接跳过（约 1.5 秒），不会把验证码次数耗光
- **失败原因可追溯**：失败项会带上具体原因（验证码连续失败、无全文、0 字节、状态码等），而不是笼统的"下载失败"
- **PDF 完整性校验**：校验 `%PDF-` 文件头 + 文件大小，避免把错误页面或截断文件当成 PDF
- **交互式菜单**：无需任何参数，`python main.py` 直接上手

## 环境要求

- Python 3.9+（开发与实测环境为 3.12）
- Windows / macOS / Linux 均可

> `ddddocr` 依赖 onnxruntime，首次安装体积较大；Linux 无图形界面环境也能正常运行。

## 安装

```bash
pip install -r requirements.txt
```

## 快速开始

```bash
python main.py
```

启动后是交互式菜单：

```
1. 搜索标准并下载          # 关键词搜索，列出结果后选序号下载
2. 直接输入标准号下载      # 逗号分隔多个，如 GB/T 22239-2019,GB/T 28448-2019
3. 从txt文件读取标准号并下载
4. 批量搜索标准信息并导出Excel
5. 搜索单个标准详细信息
6. 创建示例txt文件
7. 退出
```

下载的 PDF 保存在**当前工作目录**，文件名为标准号（`/`、空格转下划线），如 `GB_T_22239-2019.pdf`；重名会自动加 `_1`、`_2` 后缀，不会覆盖已有文件。

## 标准号清单格式

清单为纯文本，`standards.example.txt` 是示例：

```
# 每行一个标准号；# 开头为注释行
GB/T 22239-2019
GB/T 28448-2019

# 也可用逗号、分号或制表符分隔
GB/T 20984-2022, GB/T 35273-2020
```

## 导出的 Excel 字段

| 列 | 说明 |
|---|---|
| `search_keyword` | 你输入的查询词 |
| `found` | 是否命中 |
| `standard_number` | 标准号 |
| `standard_name` | 标准名称 |
| `adopted_standard` | 是否采标 |
| `category` | 类别（推标 / 强标 / 指技文件） |
| `status` | 状态（现行 / 废止 / 即将实施） |
| `publish_date` | 发布日期 |
| `implement_date` | 实施日期 |
| `hcno` | 系统内部标识，下载时使用 |
| `error` | 未命中时的原因 |

## 2026-11 站点改版适配说明

本次更新修复了三个会导致工具**完全不可用**的问题，记录在此以便日后站点再变时有据可查：

**1. 搜索结果表格列数变化（8 列 → 10 列）**
站点在"标准号"后插入了"序号""语种"两列，旧代码是硬编码 `cells[2]` / `cells[3]` 取值，导致所有字段整体左移错位（导出的"类别"列会显示"推标"、"状态"列显示日期）。现改为**按表头名称定位列**，表头再调整也不会错位。

**2. 下载流程多了一次跳转（最隐蔽）**
验证码验证通过后（接口返回 `success`），必须再请求一次
`showGb?type=download&hcno=...&request_locale=zh_CN` 换取下载凭据，否则 `viewGb` 会返回 **HTTP 200 但内容 0 字节**。旧版本正是卡在这里，表现为"文件无效或太小 (0 字节)"。

**3. 会话处理冲突**
`/bzgk/gb/index` 已返回 404（但仍会下发 JSESSIONID）；且会话中会出现两个同名 `JSESSIONID`，手工拼 `Cookie` 请求头会命中错误的那一个，甚至抛 `CookieConflictError`。现改为完全交由 `requests.Session` 管理 Cookie。

**增强项**

- 已废止 / 未收录标准提前跳过：判据是页面上有无 `button.xz_btn`（"下载标准"按钮）。注意不能用"暂无全文"这四个字判断——它是页面内联 JS 的 i18n 字典，每个页面都有
- 失败项上报具体原因；`batch_download` 修正了 `as_completed` 顺序导致的"失败项与标准号错配"问题
- `ddddocr` 新版需要 `show_ad=False`（旧版不支持该参数，已做兼容）

## 下载速度实测

同批 6 个标准、共 36.87 MB（含 2 个已废止标准），不同并发数的实测结果：

| 并发数 | 下载耗时 | 吞吐 |
|---|---|---|
| 1 | 54.4 s | 0.68 MB/s |
| **2** | **21.0 s** | **1.76 MB/s** |
| 3 | ~20 s | 1.60 MB/s |
| 4 | 10.44 MB / 7.1 s | 1.47 MB/s |

**结论：2 并发最优，约为单线程的 2.6 倍。** 3 以上没有额外收益——瓶颈在服务端限速（总带宽约 1.5~1.8 MB/s）。单文件端到端耗时（含取码、验码、换凭据、下载）约 2~16 秒，18 MB 的文件约 14 秒。

> ⚠️ 请不要再往上加并发。工具是给个人研究用的，压测并发既不会更快，也更容易被站点拉黑。

## 可选：脚本化批量下载

`bench_batch.py` 是对同一套逻辑的脚本化封装，适合一次跑几十上百个标准：

```bash
# 用法：python bench_batch.py <并发数> <输出目录> 标准号1 标准号2 ...
python bench_batch.py 2 downloads "GB/T 22239-2019" "GB/T 28448-2019"
```

会依次完成"查询 → 下载"，并输出每个文件的耗时、大小、吞吐和总汇总。

## 常见问题

**Q：下载得到 0 字节 / 提示"文件无效或太小"**
站点改版后最常见的问题，通常是"下载凭据"没拿到。本版本已修复；若再次出现，优先检查 `showGb?type=download` 这条请求是否还返回带验证码的下载页。

**Q：提示"无全文（已废止或未收录）"**
该标准已废止（被新版取代）或系统中未收录全文，无法下载。可到系统里查该标准的最新版本号。

**Q：验证码连续失败**
ddddocr 单次识别率约 30%~50%，程序会自动换图重试（默认 10 次）。若持续失败，可能是会话被站点标记，重开程序即可。

**Q：报 SSL 证书错误**
`c.gb688.cn` 的证书只匹配 `*.samr.gov.cn`，因此下载侧必须使用 `http://`（程序内已固定），不要自行改成 https。

**Q：搜不到 GB 5xxxx 工程建设标准**
该系统只收录 GB / GB/T 国家标准与指导性技术文件，工程建设标准（GB 50xxx）由住建部另行发布，不在收录范围。
